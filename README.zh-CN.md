# Claude 桌面版 Collaborative Notes

[English](README.md) | **中文**

**让对话继续向前，也别让重要的事丢了。**

Collaborative Notes 位于 **Claude 桌面版 Code 标签页**的对话旁边。你可以随手记下想法、问题、决定和待办，不必打断正在进行的对话；需要时，再回到它们来自的那段原文。

> **一个供人和 Agent 共同管理注意力的工作区：事情可以离开主线，但仍留在协作之中。**

Collaborative Notes 是一个人机协作插件。它不是普通笔记本、任务管理器、长期记忆或知识库，而是在当前对话旁边提供一个**共享的临时工作区**，帮助你和 Agent 决定什么现在还需要占据注意力、什么可以先放下，以及需要时怎样准确地带回来。

**首个公开版本：0.1.0。** 插件名为 `collaborative-notes`，市场名也为 `collaborative-notes`。目前确认的宿主范围是 macOS 上的 Claude 桌面版 Code 标签页。Windows 代码路径和 CI 检查已经具备，但尚未在 Windows 上实际运行 Claude 桌面版验证。

本项目延续 [Collaborative Notes for DeepSeek Harness](https://github.com/aprilxuMLC/dsh-collaborative-notes)，共享同一套产品契约。Claude 桌面版的实现见 [Claude 桌面版适配规范](docs/claude-desktop-adapter.zh-CN.md)（[English](docs/claude-desktop-adapter.md)）。

# I. 它是什么，它为什么重要

### 对话是线性的，工作不是<br>
**Conversation is linear. Work is not.**

真实工作会不断产生旁支。东西一直留在对话里，主线会越来越重；东西随手扔进另一个笔记本，又容易丢掉“它当时为什么重要”。

Collaborative Notes 尝试提供第三种选择：

> **让一件事离开当前主线，但不离开协作。**

这背后不仅是一个记忆问题，也是一个注意力问题。

### 注意力稀释<br>
**Attention Dilution**

长程协作中，即使所有历史、文件、memory 和 Notes 都还存在，Agent 仍然会面对另一个问题：随着越来越多事项同时保持“可能相关”，此刻真正应该关心什么会越来越难判断。信息没有丢失，协作却未必更清晰；真正重要的约束可能被越来越多“也许有用”的状态稀释。

Collaborative Notes 尝试把**注意力本身也变成一种可以共同管理的资源**。当前真正需要的内容继续留在主线；其它内容一旦被可靠安置，就可以退出 Agent 的持续注意力，之后再由用户或当前任务重新带回前台。

这里利用了一种朴素的人机差异：人不需要把所有事项持续塞进 active context。一个容易浏览的共享工作面可以提供成本很低的外围注意力——看一眼、置顶、勾选，或者说一句“把这个拿回来”。Agent 则在需要时沿明确入口重新读取和恢复上下文。

> **人类的低成本外围注意力 + Agent 的按需重新激活。**

它能否在不同用户和长程任务中稳定降低认知负担、提高任务质量，目前仍是需要继续验证的产品假设。

### 记忆不等于注意力<br>
**Memory ≠ Attention**

“以后还能找到”和“现在还应该持续关注”不是同一个问题。Collaborative Notes 允许已经可靠安置的事情不再占据持续注意力：延后工作、知识候选和复盘素材可以退出主线，而不是永远跟着对话往前走。

> **还存在，不等于现在必须持续关注。**

安全放下只有一半，另一半是以后真的还能回来。对于来自具体对话内容的 Note，Collaborative Notes 保留它和原始讨论之间的来源关系；重新处理时可以回到真正的 source，而不是靠全文搜索或模型猜测找一个“差不多在这里”的位置。

> **释放注意力，不等于丢失返回原始语境的路径。**

当前 Agent 不必在记录时预测未来所有的上下文需求。未来有读取权限的 Agent 或工作流，可以先读 Note，再沿保存的来源回到原始讨论，并按自己的任务补读足够的上下文。

> **保存未来上下文的把手，而不是预先打包未来上下文。**

所以 Collaborative Notes 刻意保持一个小核心：记录、暂存、路由、来源关系和重新激活；真正的后续加工由不同的消费者完成：

| 便签 | 未来消费者 | 后续工作 |
|---|---|---|
| **L1 会话待办** | 你和本对话里的 Agent（包括它的分支） | 到时机时带回、讨论解决，然后关闭 |
| **L2 延后工作** | BACKLOG / 工作规划 Agent | 排序、合并、安排、执行 |
| **L3 知识候选** | 知识整理 Agent / Workflow | 核验、去重、重组、正式沉淀 |
| **L4 复盘素材** | 复盘 / Agent improvement Workflow | 复盘、验证、接受，再决定是否改变 Rule / Skill / Prompt / Workflow |

> **候选状态，不是正式状态。**记下来只表示值得以后处理，不表示后续处理已经完成。

默认方式是**用户主导记录，人和 Agent 协作维护**：

- Agent 可以帮你写好一条你决定保留的便签，也可以提出建议；建议本身不算记录。
- 它不会扫描普通对话来挖掘便签，也不会在记录时自动去重或合并。
- 便签**默认只属于当前对话**。只有你在这次请求里点名其它对话，它的便签才会进入当前 Agent 的工作。

> **默认局部，需要时明确取用。**

# II. 现在能做什么

## 能力速览

- **原生面板，就在对话旁边。** Notes 使用宿主提供的插件面板。在已经设置过的项目里，面板会自动打开；`/notes` 可以打开面板，并在新项目中启动设置。你也可以让 Claude 打开面板。
- **四条分道，按去处分。** L1 会话待办 · L2 延后工作 · L3 知识候选 · L4 复盘素材。分道说明想法应该去哪里，不表示紧急程度。设置时选择的分道显示名称会应用于所有项目，且只用于显示，不会更改分道 key 或文件。
- **基本功能。** 搜索四条分道、排序、置顶、编辑，并在确认后删除。只有你能删除。
- **精确来源，如实返回。** 引用便签会分别保存你的想法、选中的原文和原文所属消息。点 **↪ 回到来源**，默认显示被引用的那一轮并高亮所有精确匹配；还可按需展开前后对话。状态会说明原文精确匹配、不再精确匹配或无法读取。宿主原消息也会短暂显示黄色边框。来源不会靠猜，也不会改绑到相似文字。
- **面板不能选中文字，也能引用。** 在对话里复制文字，再点 **📋 引用已复制的文字**；或者用 **🔍 在对话中查找** 搜索整段对话（包括已压缩的部分），在目标轮次中点选首尾句。引用不会新建对话轮次。
- **Agent 知道如何配合使用便签。** 插件附带 `collab-notes` skill 和进程内 Agent 工具，可按要求读取、写入和编辑普通便签、回到引用来源、打开面板。Agent 不会删除便签，也没有创建引用的工具。它可以处理本对话便签；只有你点名时，才只读访问其它对话。写入或编辑后面板立即重绘，不需要刷新。
- **由你决定带回什么、何时带回。** 在便签卡片上勾选 **☐ 附到下条消息**；面板里的勾选列表和输入框上方的一行会提示将附上几条，也可以在那里移除。你接下来发送的消息会带上隐藏的协作上下文，并标明这是协作资料而非指令。成功发送后，插件会尝试在对话记录中找到该消息并显示 📎 回执；找不到时不会显示。若已勾选的便签被删除，插件会取消勾选并暂缓消息，要求你重新发送。其它附加失败会暂缓消息并保留勾选；没有勾选时，Notes 故障不会阻止消息。
- **分支时保留你的位置。** 新分支的面板会询问一次：带入全部便签、按分道选择，或不带。已有内容的分道可以选择合并（父分支优先）、保留或替换。引用来源在分支点之后的便签留在原分支；带入的便签会获得新 key，之后两边独立演进。接着旧对话开的新会话（对话记录开头带着旧对话）也会询问一次。
- **普通文件，可供下游工作流使用。** 便签采用共享的 `dsh-note v1` Markdown 区块格式，Agent 和工作流都可以直接读取。格式和来源字段见第 IV 部分。
- **语言切换与帮助。** 可在面板标题栏切换中文/English，选择会被记住。首次使用遵循系统语言；插件无法读取应用自身的界面语言。点 **?** 查看帮助。

## 用起来是什么样

**不打断思路，随手记一笔。** 在面板里写便签、选择分道即可。对话中不会多出一轮消息。

**引用你选中的原文。** 在对话里选中文字并按 ⌘C，再点消息输入框上方或面板里的 **📋 引用已复制的文字**。插件会搜索整段对话。只在一条消息里找到时，就关联到那条消息；如果多条消息都匹配，会像搜索结果一样列出来，打开一条后点 **引用到这条消息**。如果文本和上次引用相同，面板会问是否再引用一次。剪贴板不会被清空。匹配可以容忍弯引号和可见的 `**` 标记。找不到时会显示提示，建议缩短为一段普通文字或改用 🔍。

**找回并引用更早的内容。** 点 **🔍 在对话中查找**，浏览最近 10 轮及摘要，每次加载更早的 20 轮；也可搜索整段对话，包括已压缩部分。打开目标轮次，点选第一句和最后一句，再点 **引用选中的文字**。这只会创建便签，不会向对话发送消息。

**把对话遗忘的细节带回来。** 长对话压缩后，Claude 可能已不记得早期细节，但便签仍保存原话及其来源。勾选便签，让下一条消息把它作为协作上下文带给 Claude；也可以让 Claude 回到便签来源重读原讨论，或点击面板中的 **↪ 回到来源**。

**让关键约束随时在手边。** 长对话中，`CLAUDE.md` 或 `AGENTS.md` 里的规则可能逐渐淡出注意力。把最重要的几条约束记成便签并置顶；工作接近其中一条时勾选它，下一条消息就会把它重新放到 Claude 面前，**📎** 会显示它已随消息发出。

**把选中的便签带进下一条消息。** 在便签卡片上勾选，面板和输入框上方会提示将附上几条。下一条消息会携带隐藏的协作上下文。发送后，插件会在约 10 秒内重试几次，在对话记录中找到该消息并添加 **📎 附了 n 条便签：…**；找不到时不显示这一行。

**回到原始语境。** 从便签打开来源，查看引用所在轮次；只有引用精确匹配时才高亮，否则显示整条消息且不高亮。来源不可用时仍显示已保存的引用，也可以继续展开任意数量的前后轮次。插件不能滚动宿主的原生对话记录，所以对应消息会短暂显示黄色边框。若来源属于另一段对话，插件会先询问；只有应用确认认识那段对话时才显示 **↗ 打开原对话**。

**让 Claude 帮你处理便签。** 可以这样说：“把这条记到 L2：发布后重新检查缓存”“给那条 L1 便签补充：测试已通过”或“我的 L3 便签写了什么？”也可以点名另一段对话，例如“读取我和 API 设计有关的那段对话中的 L3 便签”。跨对话访问为只读；打开其来源前需要确认。成功写入或编辑后面板会立即更新。

**分支时选择需要的上下文。** 分支会询问带入全部便签、按分道选择或不带。对于已有的分道，可选择先合并父分支、保留分支内容或替换。引用来源在分支点之后的便签留在父分支。

**准备下游知识。** 单独的 Agent 或工作流可以收集某个主题的 L3 便签及其来源讨论，起草知识库条目供你审阅。L2 可用于后续规划；L4 可在审阅后用于总结经验。

# III. 安装、第一次使用与支持范围

## 安装

需要 Claude 桌面版，以及终端里的 `claude` 命令（Claude Code 命令行）。在终端运行：

```sh
claude plugin marketplace add aprilxuMLC/claude-collaborative-notes
claude plugin install collaborative-notes@collaborative-notes
```

然后重启 Claude 桌面版。

**更新：**

```sh
claude plugin marketplace update collaborative-notes
claude plugin update collaborative-notes@collaborative-notes
```

更新后重启应用。

**卸载：**

```sh
claude plugin uninstall collaborative-notes@collaborative-notes
```

便签以普通文件形式留在项目的 notes 文件夹中。绑定、勾选、标记和语言偏好保存在插件 store：`~/.claude/plugins/store/`。

## 第一次使用

1. 在 Claude 桌面版的 **Code** 标签页打开一个项目。已完成设置的项目会自动打开旁边的 Notes 面板。没有设置 Notes 的项目只会提示一次输入 `/notes`，其它时候保持安静。输入 `/notes` 即可打开面板并开始设置；也可以让 Claude 打开面板。
2. 为当前项目文件夹设置 Notes。默认便签根目录是 `<project>/notes`。可以通过文件夹浏览器选择其它位置（上一级、隐藏文件夹列在最后、新建文件夹），也可以直接输入路径。所选文件夹若已有 Notes 分道，设置会复用它们。便签根目录丢失时插件不会悄悄重建。
3. 按提示选择四条分道的显示名称；这些名称应用于所有项目。可随时在面板标题栏切换中文/English。首次使用会遵循系统语言。
4. 试着写一条便签、引用一段原文、勾选一条便签供下一条消息使用，或让 Claude 读取、编辑便签。点标题栏的 **?** 查看帮助。

点 × 关闭面板后，至少五分钟后发送消息，面板会重新打开。发送 `/notes` 或让 Claude 打开 Notes 也可以重新打开。

## 支持范围

**已验证：** macOS 上的 Claude 桌面版 Code 标签页。

**未宣称支持：** Claude 桌面版 Chat 或 Cowork、浏览器中的 claude.ai、移动端，以及作为用户宿主的 Claude Code CLI 和 IDE 扩展。有些工具可能能在 CLI 中运行，但面板可能不会显示。

**Windows：** Windows 代码路径已经具备，包括剪贴板、文件、链接、编辑器操作的 PowerShell 处理以及盘符路径。2026-10-04，GitHub `windows-latest` 和 `macos-latest` 上的 CI 单元测试和插件验证通过；这不能验证 Windows 上的 Claude 桌面版，该平台尚未试用。

**已知限制：**

- 打开或关闭宿主文件面板的按钮常常需要点两次。
- 应用重启后，面板会和对话一起绘制。通常几秒内出现，偶尔可能需要几十秒。
- 如果 `/notes` 是全新会话的第一条消息，Claude 可能会在插件准备好之前收到它。此时 Claude 可能会自行打开面板；否则再输入一次 `/notes`。
- 面板输入框是单行的。便签根目录位于会话项目文件夹内时，长便签使用应用文件面板；否则使用系统文本编辑器（macOS TextEdit 通过 `open -t` 打开，Windows Notepad）。文件面板自动保存，插件跟随每次保存；文本编辑器中的更改会在文件保存后读回。
- 引用范围是单条用户或助手消息中的文字，一次一条；不包括推理、工具调用、工具输出或文件更改。
- 删除不可恢复，没有回收站。便签是普通、未加密的 Markdown 文件；是否同步取决于所选文件夹。直接在插件外（包括其它编辑器或 shell）修改分道文件可能造成版本冲突。
- 窄窗口尚未测试。
- 暂无流畅的面板内滚动；可用 **↑ 回到顶部**。

**与 Codex 版本的不同：**

- Notes 是宿主的原生插件面板，不是浏览器页面。
- 面板内不能选中文字，因此引用通过复制后匹配，或点选句子完成。
- 回到来源的内容显示在面板中；插件无法滚动原生对话记录。
- 勾选的便签作为隐藏上下文附加到下一条消息；之后插件会尝试在那条消息下添加 📎 回执。Claude 回复期间排队发出的消息不显示 📎。极少数情况下（文字相同的较早消息延迟写入），📎 可能标在那条较早的消息下；便签本身始终随你发出的那条消息送达。
- 写入或编辑后面板会重绘，不需要刷新。
- 面板标题栏提供中文/English 切换；`/notes` 可打开面板并启动设置。
- 长便签在项目文件夹内使用应用文件面板，否则使用系统文本编辑器；保存后读回更改。
- 关闭面板后，至少五分钟后发送消息会重新打开；这一点与 Codex 版本相同。

## 插件读取哪些内容

插件会读取便签根目录、自身的 store、当前对话的对话记录（transcript JSONL），以及分支检测和继承期间的父对话的对话记录。只有点名某段对话时才会读取其它对话的对话记录。只有点击 **📋 引用已复制的文字** 时才读取剪贴板；设置期间会列出文件夹；在你选择界面语言之前，每次会话开始时检查系统首选语言。它还会在便签根目录下创建并读取临时编辑器文件及 `.editing`、`.carry-over` 路径，并使用操作系统命令访问剪贴板和语言信息、移动或删除文件、处理文件夹、打开链接及启动编辑器。应用会话元数据（`get_session`）仅用于提供 **↗ 打开原对话**。插件本身不发起网络请求；勾选的便签只会作为你本人消息的一部分到达模型。

# IV. 给下游 Agent 和工作流

便签是普通 Markdown 文件，每个分道、每段对话各一个文件：

```text
<便签根目录>/<lane>/<sessionId>.md
```

每个文件包含带 item key 的 `dsh-note v1` 区块。元数据包括 `dsh-meta host: claude`；有来源的便签会保存 `{ "sessionId": "…", "messageId": "…" }`，其中 `messageId` 是 transcript 条目的 UUID，同时保存精确原文和用户写的便签。无来源和有来源两种格式都沿用 DSH / Codex 共享格式。

设置时会询问分道显示名称，并应用于所有项目；名称覆盖配置以 `laneConfig` 保存在插件 store。四条分道本身仍是 L1 会话待办、L2 延后工作、L3 知识候选和 L4 复盘素材。

分道文件的版本令牌是该文件的 SHA-256。写入采用 compare-and-swap，并先写临时文件再移动到目标位置。这样发现版本过期时可以报告冲突，而不是静默覆盖并发修改。

你要求下游处理时，单独的工作流可以收集某个主题的 L3 知识候选及其来源讨论，起草条目供你审阅。L2 可用于规划，L4 可用于经验复盘；经审阅前，这些文件仍只是候选。

分支带入记录保存在：

```text
<便签根目录>/.carry-over/<child>.json
```

标记采用 Codex 格式 v2。带入分支的便签会获得新的 item key。下游消费者可直接读取 Markdown 文件，并沿有来源便签的 `{sessionId, messageId}` 找到 transcript 条目，再根据任务需要读取周边上下文。L3 和 L4 在经过人工审阅并接受之前，仍只是候选。

Agent 工具包括 `notes-read {lane, session?}`、`notes-write {lane, content}`、`notes-edit {lane, itemKey, content, expectedVersion}`、`notes-source-reentry {lane, itemKey, contextWindow?, before?, after?, session?}` 和 `notes-open-panel {}`。写入创建普通便签；编辑使用 item key 和预期版本。没有删除工具，也没有引用工具。只有用户点名时才能只读访问其它对话。`collab-notes` skill 说明了 Agent 应如何配合使用这些工具。
